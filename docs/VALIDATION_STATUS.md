# Validation status — check before submitting the release

The Python source was syntax-checked in the authoring environment. Mesa 3.5.2 could not be installed in that environment because its package index was unreachable, so the local compatibility-shim checks do **not** verify the model against the actual Mesa package.

A GitHub Actions workflow is included at `.github/workflows/ci.yml`. On a push to `main`, it creates a clean Python 3.12 environment, installs the pinned dependencies, runs the unit tests, runs the preserved Mesa tutorial example, runs the project baseline/alternative experiments, and uploads the regenerated outputs as a workflow artifact.

Before creating the DEL02 release:

1. Open the repository's **Actions** tab.
2. Confirm the **Mesa prototype checks** workflow completed successfully on the commit you intend to submit.
3. Inspect the uploaded `del02-model-outputs` artifact and verify that the CSV and graph files are present.
4. If the workflow fails, use its logs to fix the code or dependencies and push the correction.
5. Update the DEL02.1 report so any results described match outputs generated by the successful Mesa run.
6. Only then create the annotated `DEL02` tag and the GitHub release named `DEL02 Release`.

The checked-in CSV/SVG outputs are provisional logic-check outputs generated with a temporary test-only compatibility shim. They include a `validation_status` field where applicable and are not verified Mesa 3.5.2 outputs. Do not describe them as Mesa-generated results.
